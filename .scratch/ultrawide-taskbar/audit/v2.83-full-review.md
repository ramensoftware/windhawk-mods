# Windows 11 Better Ultrawide Taskbar v2.83 — full audit

## Scope and purpose

- Reviewed implementation: `mods/windows-11-better-ultrawide-taskbar.wh.cpp`, version 2.83, 3,465 lines at review time.
- Review date: 2026-09-22.
- Audience: the engineer implementing and verifying the corrections.
- Scope: the complete current mod, not a commit diff; correctness, structural soundness, CPU efficiency, and GPU/rendering efficiency.
- The older misspelled `windows-11-beter-ultrawide-taskbar.wh.cpp` was not the target.
- Original review was read-only. This document records the original findings; the implementation ledger below will record subsequent fixes without rewriting that historical evidence.
- Line numbers in findings refer to v2.83 and will move during implementation. Function names are the stable navigation aid.

## Verdict

The compositor-driven layout is a sound foundation. Capture resizing, source lifetime/invalidation, fallback recovery, and the relationship between optical and animated geometry need corrections. A successful compile is not proof of those behaviors.

Thirteen findings: one high priority, eleven medium priority, one low priority. No live-Explorer crash was established. The isolated XAML harness crashed; that is a verification failure, not evidence that the installed mod crashes.

### Evidence terminology

- **Source-confirmed:** the defect's control flow or conflicting invariants are directly visible in the inspected implementation. Its user-visible manifestation is an inference unless explicitly reproduced.
- **Isolated reproduction:** production functions exercised in a separate process without modifying Explorer or capturing the desktop.
- **Mathematical counterexample:** a deterministic input contradicts the geometry or arithmetic claim, without claiming a screenshot reproduction.
- **Unverified runtime concern:** not promoted to a defect without sufficient evidence.

## Correctness findings

### C01 — recreate capture buffers when content size changes

**Evidence:** `LiquidRenderer::CreateSource`, original lines 1524–1530; `OnFrame`, 1614–1643. Source-confirmed against the documented Windows Graphics Capture contract.

The pool is created at the initial `GraphicsCaptureItem.Size()`. `OnFrame` reads the texture description but never `frame.ContentSize()` and never calls `pool.Recreate()`. It does update `source.rect` to the latest `GetWindowRect`.

**Trigger:** a captured application grows, shrinks, or maximizes while it remains a capture candidate.

**Consequence [INFERENCE]:** larger contents are clipped to the old capture allocation; smaller contents leave undefined pixels outside ContentSize. Rendering maps this clipped/padded texture over the new rectangle, producing incorrectly scaled or stale backdrop content.

**Correction:** track pool size and per-frame ContentSize, copy only valid pixels, and recreate the pool when size changes after releasing the frame. Do not confuse texture allocation bounds, valid content bounds, screen bounds, and copied-region bounds.

**Verification:** capture a synthetic patterned window, grow and shrink it while it stays eligible, and inspect resulting dimensions/pixels. Verify no undefined region is sampled. Exercise the real production frame-handling path rather than only a rectangle helper.

**Primary source:** https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture#process-capture-frames and https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.direct3d11captureframepool.recreate

### C02 — invalidate output on scene changes

**Evidence:** `LiquidRenderer::UpdateSources`, original lines 1563–1597; timer dispatch calls `UpdateSources` followed by `FlushPendingPresent`.

Membership, z-order, and existing source rectangles are changed without marking the output dirty. The flush does nothing when `pendingPresent` was false.

**Trigger:** static overlapping windows are reordered, moved, minimized, or removed without another surviving source producing content changes.

**Consequence [INFERENCE]:** old pixels or stacking remain until an unrelated frame/layout event causes rendering.

**Correction:** compare the ordered source scene and invalidate for membership/order/geometry changes. Send invalidations through the common rendering scheduler.

**Verification:** establish a settled synthetic scene, then remove or reorder one source without delivering a new frame to the remaining sources. The next scheduled render must show the new scene.

### C03 — publish a source before starting capture

**Evidence:** `CreateSource`, original lines 1531–1543; `UpdateSources` publishes the completed list later; `OnFrame` source lookup at 1621–1623.

`CreateFreeThreaded` callbacks can run after `StartCapture` but before the new source enters `sources`. The callback consumes a frame and drops it when lookup fails.

**Trigger:** the first capture frame arrives during creation of this or another candidate source.

**Consequence [INFERENCE]:** the initial frame is lost; a static source remains absent until another content update.

**Correction:** publish before starting capture, or address a weak source object directly from the callback so its initial frame survives before scene publication. Avoid strong callback cycles.

**Verification:** make first-frame delivery precede final scene publication; the source's first image must remain usable. Verify late callbacks cannot target a new capture solely because its HWND was reused.

### C04 — commit texture and view atomically

**Evidence:** `OnFrame`, original lines 1627–1640 and failure handler 1651–1659.

After successful texture allocation and failed SRV allocation, the texture survives. A same-size next frame skips the allocation branch, so the missing SRV is never recreated. A healthy device does not trigger renderer-level retry.

**Trigger:** transient `CreateShaderResourceView` failure after `CreateTexture2D` succeeds.

**Consequence [INFERENCE]:** source is skipped indefinitely by `RenderLocked`.

**Correction:** create the texture/view pair in temporaries and publish only after both succeed; retain or invalidate previous usable resources deliberately.

**Verification:** inject one view-allocation failure, then success; subsequent same-size content must be displayed without recreating the whole mod.

### C05 — one presentation policy and timely wake-up

**Evidence:** `PresentLocked`, original lines 1439–1457; `OnFrame`, 1644–1650; `ArmLiquidTimer`, 2508–2511.

Geometry/flush producers use 17 ms, but capture callbacks directly render after 14 ms. The only guaranteed deferred flush is the 250 ms source-discovery timer.

**Trigger:** staggered capture callbacks arrive 14–16 ms after a prior presentation, or a final geometry update is throttled and no further frames/layouts arrive.

**Consequence [INFERENCE]:** redundant full GPU submissions and a deferred update waiting almost 250 ms. Rendering holds the same mutex needed by UI-side geometry updates, so any Present blocking is shared; actual GPU stalls were not measured.

**Isolated reproduction:** production renderer initialized successfully; a geometry change remained `pendingPresent=1` after 45 ms idle; explicit `FlushPendingPresent()` changed it to zero with `Failure()==S_OK`.

**Correction:** one invalidation/presentation scheduler shared by frames, geometry, and scene changes. Schedule a wake-up at the rendering deadline; keep slow source discovery separate. Do not shorten all discovery polling merely to repair rendering latency.

**Verification:** a single throttled final change must render by its deadline without another capture/layout event. Mixed producers must not bypass the same rate gate. Validate shutdown cancels scheduling safely.

### L01 — retire roots instead of retaining stale HWND ownership

**Evidence:** `WithdrawTray` and `PublishTray`, original lines 1910–1940; `WatchFrame`, 3225–3234; `g_roots.clear()` only at global teardown.

The old Root strongly holds its frame and retains `taskbar` after withdrawal. A newly discovered frame on the same HWND collides with that stale association on every publication attempt.

**Trigger:** frame recreation while the native taskbar HWND survives, or taskbar destruction/reuse without root retirement.

**Consequence [INFERENCE]:** replacement frame remains native indefinitely; stale roots also retain references/resources and subscriptions until unload.

**Correction:** explicit retirement for detached/replaced roots, including subscriptions, visual state, capture resources, and HWND association. Do not erase a root while an iteration/reference into `g_roots` is active.

**Verification:** replace a root on a stable synthetic taskbar HWND and confirm the replacement can publish while the old root has no subscription or ownership. Test destruction/recreation and ordinary temporary fallback separately.

### L02 — keep expected fallbacks retryable

**Evidence:** `UpdateFollower` throws E_BOUNDS at original line 2788; `OnLayout`, 3064–3069, blocks after ten exceptions.

A capacity condition documented as recoverable shares the permanent-failure counter.

**Trigger:** more than 64 realized children persist for ten layout passes, then capacity returns below the limit.

**Consequence [INFERENCE]:** root remains blocked until the mod reloads, contrary to embedded documentation.

**Correction:** separate expected capacity/transient geometry states from hard errors and ownership loss. Perform the capacity check before allocating/reworking plate visuals.

**Verification:** exceed capacity beyond the former retry limit, return below it, and observe successful docking. Ownership loss must still retain its deliberate native fallback behavior.

### L03 — preserve later opacity ownership/state changes

**Evidence:** `PrepareStatePlate`, original lines 2138–2151.

Opacity is sampled once and written on every refresh without verifying the current value still belongs to the mod. Native mode also needlessly acquires this property even though it does not dim it.

**Concrete integration:** `mods/windows-11-taskbar-styler.wh.cpp`, original lines 2748–2749, contains `Opacity@NoRunningIndicator=0`.

**Consequence [INFERENCE]:** state transitions are pinned to a stale snapshot or later external changes are overwritten; cleanup may restore the original snapshot after the newer value was already lost.

**Correction:** avoid ownership where no change is needed; check ownership before reapplying; preserve binding/local-value semantics. Do not merely re-pin a new numeric default. Any template-driven dimming strategy must remain compatible with native state animation.

**Verification:** change opacity after acquisition, refresh, and restore; the external change must survive. Verify Native leaves local-value/binding state untouched. Check state transitions from initially hidden and initially visible plates.

### V01 — compensate rim alpha only for real dimming

**Evidence:** `ButtonRim`, original lines 2107–2118; Native opacity branch at 2145–2148.

The gradient alpha is always divided by 0.32, while Native leaves opacity unchanged.

**Isolated reproduction:** actual production Composition brush emitted dark top alpha 81 instead of reference 26. Bottom alpha similarly becomes 47 instead of 15. Native has no compensating multiplication.

**Correction:** use the actual dimming ratio or avoid duplicating the native rim where it is preserved. Keep intended border-setting semantics explicit.

**Verification:** compare final effective alpha in Native and dimmed themes, including non-unit original opacity. Test rendered behavior rather than pinning the internal constant alone.

### V02 — exclude retired sources from optical lenses

**Evidence:** `AddButtonLenses`, original lines 2525–2530; source retention at 2829–2835; shader first-hit selection at 1150–1168.

Retained sources include retired buttons waiting for parking/reuse. The follower filters them, but the lens producer does not.

**Consequence [INFERENCE]:** ghost refraction or stale alert color, potentially shadowing a live overlapping lens.

**Correction:** share the explicit eligibility/lifecycle decision across follower and optical consumers, without prematurely forgetting hiding buttons.

**Verification:** retire a button whose old slot remains eligible; no lens should remain. Active and deliberately hiding sources should follow their intended transitions, including cancellation/reuse.

### V03 — represent the actual shape intersection

**Evidence:** `AddButtonLenses`, original lines 2584–2592.

`max(nativeRadius, clipRadius)` is invalid when the radii belong to different rectangles. An inset clip does not relocate the native rounded corners.

**Mathematical counterexample:** native bounds `(0,0,64,48)`, radius 8; clip bounds `(0,12,64,24)`, radius 0. At `(0.5,12.5)`, native and clip signed distances are both -0.5 (inside), but the generated inset-radius-8 lens distance is 2.6066017 (outside).

**Consequence [INFERENCE]:** native tint/rim and optical refraction disagree at inset corners, especially with small configured radius and larger vertical padding.

**Correction:** evaluate the intersection of native-border and owned-clip shapes in common transformed coordinates. Use the same intersection for coverage and optical normals; do not substitute an unrelated bounding radius.

**Verification:** render inset/square/asymmetric-corner cases and compare mask coverage with the native clipped shape. Retain the counterexample as a focused regression.

### V04 — synchronize optical geometry with animated geometry

**Evidence:** `HoldLiquidGeometry`/`DeferLiquidShrink`, original lines 1801–1826; settled lens geometry at 2648–2669; compositor expressions at 2890–2921.

Composition continuously animates the outline from the native anchor. The shader receives final layout dimensions or a held old shape through hiding and the 700 ms shrink delay. Clipping the static optical image does not synchronize its rim/refraction with the moving edge.

**Consequence [INFERENCE]:** optical edge stays at old/final perimeter during motion and snaps later; per-button lens positions are also sampled independently of per-frame native motion.

**Correction:** establish an authoritative current geometry path shared by the shader and outline. Preserve native compositor-driven taskbar motion; do not invent an easing curve. Distinguish genuine compositor readback limitations from claims of exact synchronization. Remove obsolete hold/delay logic once replaced.

**Verification:** actual enter/exit/reorder motion with static captured content, including per-button lenses. Observe correspondence throughout the transition, not just the settled endpoint. A build or helper test cannot prove visual synchronization.

### V05 — refresh rims after theme changes

**Evidence:** `PrepareStatePlate`, original lines 2222–2228.

ActualTheme is used only when creating a rim. Existing fixed-color gradients do not update, unlike the dock material's theme handling.

**Consequence [INFERENCE]:** white dark-mode rims remain in light mode, or black light-mode rims remain in dark mode, until recreation/reload.

**Correction:** track/update the applied rim theme while retaining child-visual ownership checks.

**Verification:** switch a synthetic plate between light and dark without replacing it; effective rim colors must change, and an external child visual must not be overwritten.

## Structural assessment

### Preserve

- Compositor expressions follow native movement instead of reproducing easing on the CPU.
- Measurements centralizes geometry for the layout pass.
- Canonical COM identity plus weak element references avoids trivial source identity confusion.
- Ownership checks preserve most external brush/clip/transform writes.
- Weak renderer callback capture avoids a strong ownership cycle.
- Stop moves sources out under the mutex and closes capture sessions outside it.
- Owned textures do not retain a borrowed WGC frame surface after frame release.
- Composition uses bottom-to-top premultiplied alpha blending.
- C++/HLSL constant-buffer layout agrees: the original 64-byte header, three 64-element float4 arrays, and 16-byte tail total 3,152 bytes.
- Shader output is premultiplied, covered button pixels skip dock shading, and optional blur is half-resolution.

### Improve

Single-file distribution is a repository convention, not itself a design flaw. Keep that packaging.

Clarify internal ownership of root lifetime, capture-source lifetime, and presentation scheduling. Make retained versus visible sources explicit. Distinguish restore-now, retry-later, and permanently-blocked states. Avoid adding interfaces that merely forward calls or exposing thread/ordering requirements across more callers.

## Efficiency opportunities

### E01 — reduce full-window copies

Original OnFrame retains/copies the full source before its render-rate gate, while composition uses only the taskbar intersection. One 5120x1440 BGRA source costs 28.125 MiB of copy payload per delivered frame, approximately 1.64795 GiB/s at 60 fps. Two capture buffers plus the owned texture nominally consume 84.375 MiB for that source, excluding driver overhead. These are arithmetic estimates, not measured performance bottlenecks.

Crop the owned copy to the relevant sampling region, including any optical/blur margin required by the real sampling domain. Track its position and valid content bounds. Do not keep frame.Surface after returning the frame to avoid a copy; that violates the borrowed-surface contract. Multiple taskbars duplicating identical source captures are a profiling-led follow-up, not an excuse to introduce a shared global capture subsystem prematurely.

### E02 — reuse discovery within a refresh

PrepareStatePlates recursively discovers plates and linearly matches them. AddButtonLenses allocates another temporary vector and walks each button tree again before linearly searching statePlates. Refresh resolves taskbar publication twice.

Reuse discovered associations and same-refresh mapping results, with invalidation when Windows replaces elements. Keep correctness/ownership checks; do not cache a tree indefinitely without lifetime validation.

### E03 — cache generation-stable resources

Initialize compiles four shaders per renderer; RenderLocked reacquires the back buffer and creates an RTV each render. Cache compiled shader bytecode per process and render views per swap-chain generation; release/unbind cached back-buffer references before ResizeBuffers.

### E04 — measure shader work before complicating it

The shader already has outside-dock rejection, first-hit button selection, no dock shading under fully covering lenses, and half-resolution blur. The bounded 64-lens loop and six blur passes warrant measurement, not a speculative spatial index or proliferation of shader variants. No FPS/GPU utilization improvement was measured in the original audit.

### Failed (original run)

Command: `python .scratch/ultrawide-taskbar/glass-research/check_glass.py`

The executable returned 3221225477 (`0xC0000005`). Root cause established during the fix pass: the harness built an unhosted XAML tree (no island), where `VisualTreeHelper::GetParent(plate)` returns null, so `PrepareStatePlate` exited before installing any clip and the later `.Clip().as<CompositionGeometricClip>()` dereferenced null. Harness defect, not production. The unhosted state-plate block was removed from `glass.check.cpp`; equivalent coverage runs in an island fixture in `dock-check/fix-regressions.cpp`. Suite now passes.

### Not exercised

- Live Explorer animation/ownership and pointer hit targets.
- Real capture resizing/static-scene invalidation.
- Mixed-DPI/HDR transitions.
- Native labels and companion-mod interoperability.
- Exact cross-parent Composition visual transfer behavior.

### Rejected/unproven concerns

- Missing explicit frame.Close on early returns is not sufficient evidence of a pool leak: WGC native frame lifetime returns buffers.
- Missing ID3D11Multithread protection is not by itself an application context race when all its context calls are serialized.
- GetWindowRect versus capture bounds, HDR handling, and borderless-capture permissions require targeted runtime validation; they were not counted in the thirteen findings.
- Reparenting already-attached highlight visuals requires an isolated runtime check before being reported as a failure.
