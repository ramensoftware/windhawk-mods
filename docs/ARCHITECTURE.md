# 架构

## 原生界面

产品入口限定在 `ShellHost.exe` 的 `ControlCenter.VolumeMixerList`。先验证最窄符号能覆盖首次打开、重复打开和重新创建。Windhawk 查找确切符号，XAML 层检查运行时类型、列表容器和 `AppVolumeLevel`。每行只添加一个紧凑的按钮，复用原生 Button、Flyout 与主题资源。设备菜单使用可键盘操作的原生选项，“跟随系统默认”与显式选择互斥。

UI 在线程间传送已复制的值类型。列出设备、打开会话和调用策略在音频控制线程完成。每个附加控件按实际 XAML 容器对象跟踪。行回收、页面卸载和模块停用都应撤销事件、关闭 Flyout 并移除控件。选择确认前重新核对展示时的行标识，避免点击已被分配给其他应用的行。

## 应用和设备身份

会话管理器在 MTA 上枚举活动渲染端点与现有会话，注册 `IMMNotificationClient`、各端点的 `IAudioSessionNotification` 和所需的会话事件。注册会话通知后读取初始快照并合并重复事件，设备状态变更时重建失效的会话管理器。回调只排队，MTA 所有者处理状态与 COM 对象释放。

应用持久键优先 AUMID，其次规范化的可执行文件完整路径。包家族键仅用于能证明同包应用应共享配置的场景。同应用的多会话汇总为一条配置，每个进程身份以 PID 和创建时间复核。应用行的身份映射必须用真实 Shell 行模型证明。设备键使用 Core Audio Endpoint ID，显示名用于菜单。

## 原生策略和恢复

若快捷设置的行模型能够访问系统自带的 `PossibleOutputs` / `SelectedOutput`，单设备交互应优先研究该路径。使用菜单项时必须复核行模型和设备列表，防止热插拔改变原生索引。PID 与实际会话映射依然是过程捕获的先决条件。

在受验证的系统构建和明确的 Win11 IID 上启用私有策略适配器。路由应用前查询角色策略、记录原值和拟写值，再写入并逐角色读回。部分失败按原值回滚已成功的角色。成功后提交用户配置，应用侧延迟迁移时提示重新打开其音频流。

持久化先试 Windhawk 模块存储。配置保存目标设备和回退偏好，另存待恢复记录处理 Shell 异常退出。设备临时消失时保留偏好并回退到系统行为，恢复连接时重新评估。只有进程身份可验证且当前值仍等于模块最后一次写入时，才恢复原策略，避免覆盖用户在系统设置中的后续更改。已退出应用若无法通过私有接口安全恢复，应在下次同一应用会话可辨认时重试。这种特性必须在发布前验证。

## 多设备镜像

先验证原生会话实际落到哪个主端点，再启动镜像。实际源端点以及所有已承载该应用原始会话的端点从目标集合剔除。会话迁移中止旧镜像，待实际源端点确认后重新协调。每个符合条件的进程树只有一个 Process Loopback 采集流。父子树重叠时合并，目标集合发生变化时增减独立渲染流。

音频采集和渲染各自有 event-driven worker。渲染器分别管理有限容量队列、静音填充、掉帧计数和采样格式。Windows 共享模式转换先覆盖初版格式适配。增加每设备延迟和增益前测量 Process Loopback 是否已应用原生会话音量。镜像失效应独立停止并重试，保留主路径。同步验证使用设备填充量、采样位置和外部回放测量。主输出为原生路径，附加延迟只作用于镜像端点。

部署首选单 Windhawk 模块。当前实验在独立进程完成，生产环境是否将实时引擎移出 Shell 由线程收尾、异常恢复与长时稳定性结果决定。若需隔离，继续使用原生面板，将通信限于本机当前会话和用户，并在发布前确认 Windhawk 的交付方式。
